Detailed Description

template<rpp::constraint::decayed_type Request, rpp::constraint::decayed_type Response>
class rppgrpc::server_bidi_reactor< Request, Response >

RPP's based implementation for grpc server bidirectional reactor.

To use it you need:

  • create it via new operator: created with the call's grpc::CallbackServerContext*, the reactor completes the observable from get_observable() when the client has finished writing; created without it, only when the call has ended.
  • return it from bidirection method of CallbackService interface
  • to access values FROM stream you can subscribe to observable obtained via reactor->get_observable() (same observable emits on_completed as described above and on_error when the call is cancelled: by the client, by a deadline or by a lost connection)
  • to pass values TO stream you can emit values to observer obtained via reactor->get_observer()
Warning
grpc server reactor have to finish manually, so it is expected that you call on_completed() on reactor->get_observer(). A pipeline reactor->get_observable() | ... | subscribe(reactor->get_observer()) does it once the client has finished writing, if the reactor was created with the context.
grpc::ServerBidiReactor<Request, Response>* Bidirectional(grpc::CallbackServerContext* context) override
{
const auto reactor = new rppgrpc::server_bidi_reactor<Request, Response>(context);
reactor->get_observable().subscribe([](const Request&) { }, []() { std::cout << "DONE" << std::endl; });
reactor->get_observer().on_next(Response{});
return reactor;
}
